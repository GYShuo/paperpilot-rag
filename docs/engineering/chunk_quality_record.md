# Day 5.1 工程记录：QASPER 全量语料 Chunking 数据质量排查与优化

## 1. 项目背景

在 PaperPilot-RAG 科研论文智能问答项目中，需要将论文正文切分为适合向量检索的文本块（Chunk），再通过 Embedding 模型将文本转换为向量，构建 Dense Retrieval 索引。

前期已经完成 Section-aware Chunking 模块，支持：

- 按论文 Section 进行结构化切分；
- 将较短的相邻 Paragraph 合并；
- 将超过指定长度的 Paragraph 拆分；
- 保留 Chunk 对应的论文、章节和原始段落位置信息；
- 使用 ChunkSpan 实现原文位置追踪。

Day 5.1 的目标是将该模块扩展到整个 QASPER 训练集，并在全量 Embedding 之前进行数据质量检查。

初步结果表明，现有切分策略能够处理完整训练集，但数据中存在少量异常情况，需要进一步调查。

## 3. 问题一：发现一篇论文没有生成 Chunk

### 3.1 问题现象

全量统计发现，888 篇论文中有 1 篇没有生成任何 Chunk。

通过进一步定位，发现异常论文：

- Paper ID：`1801.07804`
- Title：`Vietnamese Open Information Extraction`
- 所在位置：训练集第 512 行
- 生成 Chunk 数：0

### 3.2 排查过程

没有直接修改 Chunker，而是分别检查原始 QASPER 数据和预处理后的 JSONL 数据。

检查结果：

| 检查项 | 原始数据 | 预处理数据 |
|---|---:|---:|
| Section 数量 | 0 | 0 |
| Paragraph groups 数量 | 0 | 0 |
| Abstract 长度 | 1029 | 1029 |
| 正文内容 | 缺失 | 缺失 |

原始数据中的 `full_text` 为字典结构，但 `section_name` 和 `paragraphs` 均为空列表。

### 3.3 根因分析

通过对比原始数据与预处理结果，确认这篇论文的正文缺失来自 QASPER 原始数据，而不是项目中的 Normalizer 或 Section Chunker 导致的数据丢失。

### 3.4 处理决策

采取以下策略：

1. 保留原始论文记录，不删除数据。
2. 不人为补充不存在的正文。
3. 不生成虚假的 Chunk。
4. 将其视为无有效正文的论文，不纳入正文向量索引。

**工程经验：** 遇到数据异常时，应首先区分数据源缺陷与代码处理缺陷，不能在没有定位根因的情况下直接修改算法。

## 4. 问题二：发现纯标点 Chunk

### 4.1 问题现象

在检查最短的 30 个 Chunk 时，发现这些 Chunk 全部是单独的英文句号 `.`。

这说明原有 Chunking 流程可能将孤立标点保留为独立文本块。

如果直接将其送入 Embedding 模型，会引入没有实际语义价值的文本。

### 4.2 全量质量统计

进一步对全部 888 篇论文进行统计，而不是只根据最短的 30 个样本判断。

结果如下：

| 指标 | 结果 |
|---|---:|
| 初始 Chunk 总数 | 59,656 |
| 纯标点 Chunk | 81 |
| 纯标点占比 | 0.14% |
| 有效短 Chunk（小于100字符） | 6,052 |

纯标点内容分布：

| 内容 | 数量 |
|---|---:|
| `.` | 71 |
| `:` | 4 |
| 其他纯标点组合 | 6 |
| 合计 | 81 |

这次统计还发现一个重要问题：

短文本不等于无效文本。

例如 `AI`、`BERT`、`x = 1` 等内容虽然很短，但仍然包含有效信息。

因此，不能简单地通过设置最小 Chunk 长度来过滤数据。

## 5. 优化方案：基于有效字符的内容过滤

### 5.1 设计思路

采用轻量级启发式规则，判断文本中是否至少包含一个字母或数字。

核心代码：

```python
def has_meaningful_content(text: str) -> bool:
    """Check whether text contains at least one letter or digit."""
    return any(char.isalnum() for char in text)
```

该方法能够识别英文、数字、中文以及其他 Unicode 字母和数字。

### 5.2 修改位置

在 `src/paper_rag/data/section_chunker.py` 中进行两处修改：

**第一处：普通 Paragraph 处理阶段。**

原有逻辑只过滤空白文本：

```python
if not text.strip():
    continue
```

修改为：

```python
if not has_meaningful_content(text):
    continue
```

这样可以避免纯标点 Paragraph 进入 Chunk 缓冲区。

**第二处：长 Paragraph 拆分阶段。**

在调用 `split_text()` 产生多个文本片段后，对每个 piece 再次执行有效内容判断。

```python
if not has_meaningful_content(piece):
    continue
```

这样可以处理长文本切分过程中产生的纯标点片段。

### 5.3 方案优势

该方案具有以下特点：

- 不依赖额外第三方库；
- 不需要引入复杂的自然语言处理规则；
- 不简单删除所有短文本；
- 普通段落和长段落切分结果使用统一规则；
- 保留原有 Chunking 架构和元数据设计。

需要注意，该方法属于启发式过滤规则，并非完整的数学公式识别机制。纯数学符号可能被过滤，未来需要根据实际论文数据进一步优化。

## 8. 工程价值与技术收获

本次工作并不是简单地删除一些无效文本，而是完成了一次完整的数据质量排查与优化。

主要收获：

1. **数据质量诊断：** 能够通过全量统计和原始数据对照定位问题来源，而不是直接修改代码。
2. **数据清洗策略设计：** 区分无语义标点与有意义的短文本，避免过度清洗。
3. **模块化开发：** 在现有 Section-aware Chunking 架构中进行最小范围修改，避免影响其他模块。
4. **测试驱动开发：** 使用新增边界测试验证过滤规则，同时通过回归测试保护原有功能。
5. **数据可追溯性：** 保留无正文论文的原始记录，避免因清洗而丢失数据来源。

### 9.2 面试时可以重点介绍的技术问题

**问题一：如何发现论文没有生成 Chunk？**

通过全量 Chunking 统计发现异常论文，再使用 Paper ID 分别查询原始数据和预处理数据，确认正文在数据源中就不存在。

**问题二：为什么不直接删除所有短 Chunk？**

因为短文本可能包含有价值的术语、缩写和数学表达式。使用长度阈值会导致有效信息损失，因此采用字符类型判断识别纯标点噪声。

**问题三：如何避免优化破坏原有功能？**

采用最小范围代码修改，并增加纯标点过滤、短文本保留、长段落拆分过滤三项边界测试，同时执行完整回归测试。
